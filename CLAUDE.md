# SkillSense AI

Skill assessment, resume analysis, placement intelligence and coding practice for students; admin tools for papers/questions/placements.

## Stack
- Frontend: React 18 + Vite (JS, no TypeScript), react-router-dom v6, framer-motion, three.js/R3F
- Backend: FastAPI + MongoDB via `motor`; JWT (PyJWT), bcrypt, slowapi rate limiting
- "AI" is rule-based scoring + TF-IDF similarity (scikit-learn). No LLM calls.

## Folder map
- `src/pages`, `src/pages/admin` - route pages; `src/components` - shared UI
- `src/services/*Service.js` - API clients (all go through `src/services/api.js`)
- `src/context` - Auth/Notification contexts; `src/utils/normalizers.js` - API response shaping
- `backend/app/main.py` - app, CORS, routers; `config.py` - settings (fails fast on bad secrets)
- `backend/app/routers` - HTTP layer; `services` - business logic; `models` - pydantic
- `backend/app/repositories` - Mongo access (P2); `data` - seed data & static config
- `backend/tests` - pytest; `backend/.env` is local only (git-ignored)

## Run
Backend (from `backend/`):
```
python -m venv .venv && .venv\Scripts\activate    # source .venv/bin/activate on mac/linux
pip install -r requirements.txt
copy .env.example .env   # then set JWT_SECRET_KEY
uvicorn app.main:app --reload --port 8000
```
Frontend (repo root): `npm install && npm run dev` (needs `VITE_API_BASE_URL`, see `.env.example`).
Data: MongoDB is required. Load starter content with `python -m app.seed` (idempotent). With no Mongo in local dev only, set `ENABLE_MEMORY_FALLBACK=true` (throwaway mongomock DB, auto-seeded, responses carry `X-Data-Store: in-memory-fallback`).
Launch on Windows: `run_skillsense.bat` or `npm run backend` (both use `backend\.venv`, never `backend\python_bin`, which lacks dependencies and makes the Vite proxy answer 500 on every `/api` call). `npm run backend:check` prints one `STARTUP CHECK OK/FAILED` line (packages, `.env`, Atlas).
Auth proof in real Chrome: `npx playwright test -c e2e/playwright.config.js auth-fix`.
Checks: `npm run build`, `pytest backend/tests`.

## Rules
- NEVER read or grep `node_modules`, `dist`, `backend/python_bin`, `backend/.venv`, `package-lock.json`.
- No silent `except: pass` around database calls; DB failures surface as HTTP 503.
- No hard-coded demo metrics or fallback mock data: every number shown comes from stored data (new user = zeros).
- All protected routes use `require_student` or `require_admin`; never trust a client-sent role.
- No secrets, default passwords or demo credentials in source or config, and no demo accounts: accounts come from registration, Google sign-in, or `python -m app.create_admin` (admin).
- Keep URLs and response shapes stable unless the task says otherwise; frontend depends on them.
- Never print or log secrets (passwords, tokens, API keys, connection strings, SMTP app passwords). Log the error type, not the payload.
- Keep API response shapes stable; add fields, don't rename or remove them.
- Ask before deleting any file or folder.
- Run the tests (`pytest backend/tests`, `npm run build`) after each change.
- Code execution: the default is `SANDBOX_MODE=online` (set `CODE_PROVIDER` in `backend/.env`; default `judge0_ce`, the free public Judge0 CE instance). No Docker and no local compilers are needed, but it requires internet. The provider URL and any API key (`CODE_API_URL`, `CODE_API_KEY`) live only in the backend; the browser only calls our own `/practice/code/run` and `/submit`. Only source code, language and stdin are sent to the provider. A slow, down or rate-limited provider returns 503/429 with a friendly message (submit: verdict `Judge unavailable`, nothing saved), never a fake success or a Wrong Answer. `subprocess` (local, dev only, not a security boundary) and `docker` (real isolation) stay in the code as alternatives; tests never call the internet (mock the provider, or run Python/Node in the local subprocess sandbox).
- Practice Arena (function-style judge, replaces the old stdin/stdout design): the student writes ONE function; a hidden driver calls it. `app/data/coding_problems.py` holds 12 original problems with `function_name`, `params [{name,type}]`, `return_type`, `examples`, `test_cases [{args, expected, hidden, large?}]` (2-3 shown, at least 8 hidden, a `large` hidden case for every medium and hard problem that makes O(n^2) or exponential code time out), `order_insensitive`, `time_limit_ms` (per case), `expected_complexity`, 3 `hints`, `difficulty_rank`. Types: int, long (kept within +-(2^53-1) so JavaScript is exact), double, bool, string, int[], long[], string[], int[][]. `services/function_judge.py` = types, generated starter code (`starter_code`, never hand-written, no hints), the `name = value` custom-input format, comparison (double tolerance 1e-6, order-insensitive arrays), `public_problem` (allow-list), `run_function_cases` (ONE provider call per Run or Submit); `services/judge_drivers.py` = the drivers for python, javascript, java, cpp, c (C only when every type is int/long/double/bool/string/int[]). Protocol: stdin = random nonce, case count, per-case ms limit, one JSON args line per case; the driver prints `@@<nonce>@@{"i","ok","result"|"error","kind","ms"}` after every case and flushes; anything else the program prints is "Stdout" (max 4 KB shown, only for shown cases). Verdicts: Accepted, Wrong Answer, Runtime Error, Time Limit Exceeded (the driver times each case, the provider kills a hung run: the case after the last flushed line fails), Compile Error (provider text with line numbers mapped back to the student's lines; `error_lines` are marked in the editor), Output Limit Exceeded (provider stdout cap is 64 KB: keep every expected result under it), Judge unavailable. A function that returns nothing (None / undefined / null) is a failed case "Your function returned nothing". NEVER return, for a hidden case, anything but its number and pass/fail: no input, expected output, error text or stdout (a student program that echoes its input used to leak it). `repositories/practice.list_public_problems` drops hidden cases and hints inside MongoDB (the list is fast; the full document is only read to judge). Endpoints: `GET /practice/problems[/{slug}]`, `GET /practice/problems/{slug}/hints?level=n` (one hint, login), `GET /practice/problems/{slug}/submissions` (own last 20), `POST /practice/code/run` (`cases`: `name = value` texts; examples as edited or custom, max 5 custom, max 8), `POST /practice/code/submit`, `GET /practice/solved`. Reference solutions (5 languages) and slow brute forces live ONLY in `backend/tests/reference_solutions.py`. To add a problem: add it to the data file, add its references (and a slow one for medium/hard), run `pytest backend/tests/test_judge.py`, then `python scripts/check_reference_solutions.py --slow --sweep --starters` from `backend/` (real provider, needs internet; prints the pass/fail tables), then `python -m app.seed`. `RUN_FULL_DRIVER_MATRIX=1 pytest backend/tests/test_judge_drivers.py` runs all 60 reference runs locally. Honest limits: needs internet; the free shared Judge0 can be slow or busy; all cases of one run share one execution (10 s CPU, 15 s wall); C is only offered for simple types; JavaScript `long` values must stay within 2^53; a determined student could forge a verdict for their OWN attempt from inside the process (the nonce is in the process memory), this is a practice tool and not an exam proctor.

- Assessment sessions (P8): `POST /assessments/{id}/start` (student only) creates or reopens (same questions, saved answers, same deadline) an `assessment_sessions` document: session_id, user_id, assessment_id, question_ids in shuffled order, started_at, expires_at = start + the set's duration; the response has NO answer keys and `seconds_remaining` for the countdown. `PUT /assessments/sessions/{id}/answers` autosaves. `POST /assessments/{id}/submit` (or `/submit`) REQUIRES `session_id`: only that session's questions are scored; another student's or an unknown session is 404, an expired one (30 s grace) is 410, a second submit is 409 (atomic `mark_submitted`, released again if storing the attempt fails). `GET /assessments/{id}` returns details with an empty `questions` list (questions only come from start) and needs login. A locked milestone cannot be started (409). `is_priority_gap` = a gap topic matches the milestone's skills/title (`matches_gaps`); the list is ordered completed, in progress, not started (priority first), locked. `courses`/`course_slugs`/`practice_sets` come only from the real `courses` and `assessments` collections (`courses_for`; a language course is only offered when the milestone or the career path names that language). `score` is the best score on a related assessment, never the seeded number. Tests that enable the limiter must call both `limiter.reset()` and `reset_default_limits()`. `npm run test:ui` signs the audit student in separately for each width because refresh cookies are single-use.
- 3D (Three.js) rule: ONE renderer per panel, created once, disposed on unmount, and a 2D fallback. Every 3D panel is `ThreePanel` (`components/three/ThreePanel.jsx`) around a lazy scene built on `engine/threeHost.js`: the scene mounts only after the panel has been on screen (IntersectionObserver) and only when `detectWebGL()` says the browser can do it, otherwise the same data is shown as a 2D version with no console output (`RoadmapTimeline2D`, the landing chips). The host caps the pixel ratio at 2, pauses the loop while the tab is hidden or the panel is off screen, uses `THREE.Timer` (never `THREE.Clock`, never `state.clock`), handles `webglcontextlost` (preventDefault, "Restoring 3D view...", "Reload 3D view" after 3 s) and `webglcontextrestored` (rebuild without deleting the dead GPU objects), and `dispose()` removes listeners, disposes geometries / materials / textures, then `renderer.dispose()` BEFORE `forceContextLoss()` (so no "Context Lost" message). Changing the data (a new career track) rebuilds the content inside the same renderer; never create a renderer per render or per track. Labels are DOM buttons positioned from the projected node (never drei `Html`), contrast 4.5:1, overlaps resolved by `resolveLabelOverlaps` (full label, then number only, then hidden). The roadmap ribbon: pure maths in `components/three/roadmap/ribbonLayout.js` (Vitest, no WebGL), scene in `sceneBuilder.js`, React in `RoadmapScene.jsx`; a plain wheel scrolls the page, zoom is Ctrl+wheel or the buttons; `prefers-reduced-motion` keeps a static camera. On Windows a file `foo.js` next to `Foo.jsx` shadows it in extension-less imports (the lazy import got the `.js` module without a default export): never give a builder and a component the same name. `@react-three/fiber` and `drei` are still installed, but `CareerReadiness3D`, `QuestionNetwork3D`, `ResumeScan3D` and `SkillNetwork3D` are NOT used by any page (they would print the R3F `THREE.Clock` warning if mounted): port them to the host before using them. Browser proof: `npx playwright test -c e2e/playwright.config.js p12-roadmap3d` (headed Chrome; also starts a second Chrome with WebGL disabled; screenshots in `e2e/screenshots/p12/`).
