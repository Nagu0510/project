## Stage D: what changed, by category

| area | how it is themed |
|---|---|
| Surfaces, text, borders | every `background`, `color` and `border` in `src/**/*.jsx|css` now reads a semantic token. A property-aware rewrite converted about 1,100 uses of the legacy `--color-*` variables and about 160 hex / rgb literals; the remaining ambiguous ones were fixed by hand |
| Status colours (badges, banners, toasts, verdicts, difficulty chips) | `--success|warning|danger|info` triples (`-soft`, `-text`, `-border`); the old light-only `#ECFDF5 / #FEF2F2 / #FFFBEB` literals are gone |
| Charts and bars | `--chart-1..6`; resume score bars use `--chart-1`, `--warning`, `--danger` |
| Code editor | CodeMirror reads `--code-*` and `--syn-*`; a Compartment reconfigures the `dark` flag, the document is never replaced. The Practice Arena editor and console panes follow the theme (light editor in light mode, forest panels in dark) |
| Three.js | roadmap ribbon and landing core keep ONE renderer; `setTheme()` swaps node and ring materials, vertex colours, emissive, light intensities and the DOM label colours in place (verified: same canvas node, one WebGL context, frames keep increasing) |
| Native controls | `color-scheme` per theme; `select option`, `optgroup`, `datalist option` read tokens (opaque `--option-active-bg` for hover/checked); `.dark-panel` still forces dark controls |
| Google sign-in | official `outline` (light) / `filled_black` (dark) button, redrawn on a theme change |
| Print | `@media print` forces the light tokens; the server-side PDF report is untouched |

### Known limits

- The browser draws the open `<select>` list itself, so it cannot appear in a screenshot. Its colours are proven by the select-contrast audit (1,404 options in the last run) instead.
- Text on gradients or images cannot be measured by the contrast audit (listed as "unjudged" warnings: the landing "Question Intelligence" section and the legend / hint of the 3D roadmap panel). Their token pairs are in the table above and they were checked by eye in the screenshots.
- There is no desktop top bar in the student or admin shell (single fixed sidebar by design), so the toggle sits in the sidebar header beside the notification bell (admin: beside the brand); on a phone it is in the top bar beside the menu button.
- The Admin proof used a stubbed session unless `ADMIN_TEST_EMAIL` / `ADMIN_TEST_PASSWORD` were set.
